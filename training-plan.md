# GitHub Copilot for Professional Productivity

## Training design

**Length:** 60 minutes  
**Format:** Live presentation, demonstrations, and audience Q&A  
**Audience:** Approximately 200 professionals in Alaska who already use some scripting or technical tools, but are not primarily professional software developers  
**Central learner problem:** “I installed GitHub Copilot. What should I do with it?”

## Outcome

By the end of the session, participants will be able to turn a real work task into a useful Copilot interaction, select an appropriate Copilot surface, improve an initial result through iteration, and verify the result before using it.

## Learning objectives

Participants will be able to:

1. Identify at least three personal productivity tasks where Copilot can accelerate skills they already have.
2. Use the **Goal–Context–Constraints–Check** prompting pattern.
3. Choose among VS Code, GitHub.com, the CLI, and the Copilot app based on where the work already lives.
4. Move from a vague request to a reviewed, usable result through conversation.
5. Apply a simple safety rule: keep ownership of judgment, sensitive information, and final verification.

## Key message

> Copilot is most useful when you bring it a real task, enough context, clear boundaries, and a way to check the result.

The session does not attempt to turn participants into professional developers. It shows them how to accelerate existing judgment, domain knowledge, scripting ability, and daily workflows.

## 60-minute run of show

| Time | Segment | Purpose |
|---|---|---|
| 0:00–0:05 | From installation to intention | Name the “blank chat box” problem and establish relevance. |
| 0:05–0:12 | Where Copilot fits | Introduce five productivity patterns and the four Copilot surfaces. |
| 0:12–0:20 | The prompting pattern | Teach Goal–Context–Constraints–Check with a weak-to-strong example. |
| 0:20–0:36 | Demonstration: one task, four surfaces | Show a realistic reporting workflow across the Copilot app, CLI, VS Code, and GitHub.com. |
| 0:36–0:45 | More workday use cases | Show examples for understanding, drafting, transforming, automating, and reviewing work. |
| 0:45–0:51 | Trust, verification, and responsible use | Explain review, sensitive data, source checking, and organizational policy. |
| 0:51–1:00 | Q&A and next action | Answer questions and have participants choose one task to try this week. |

## Productivity patterns

1. **Understand** — explain unfamiliar text, code, errors, or repository content.
2. **Draft** — create a first version of a script, checklist, issue, summary, or plan.
3. **Transform** — reformat, simplify, classify, extract, compare, or translate existing material.
4. **Automate** — turn a repeated manual sequence into a script or command.
5. **Review** — identify gaps, edge cases, risks, and opportunities to improve a result.

## Surface selection

| Surface | Best when… | Example |
|---|---|---|
| Copilot app | You are starting with a broad task, gathering context, or coordinating work. | Turn rough notes into a plan and checklist. |
| CLI | The work is in the terminal or involves files, commands, and repeatable operations. | Safely rename or summarize a folder of files. |
| VS Code | You are editing scripts, structured text, configuration, or repository files. | Create and refine a PowerShell or Python script. |
| GitHub.com | The work is already in a repository, issue, pull request, or project. | Summarize an issue and draft acceptance criteria. |

## Demonstration storyline

**Scenario:** A program coordinator receives a CSV export and rough notes every week. They need to identify incomplete records, generate a short summary, and prepare a GitHub issue describing follow-up work.

1. **Copilot app:** Convert the goal and notes into a concrete plan; identify missing information.
2. **CLI:** Inspect the CSV and propose a safe command for basic validation.
3. **VS Code:** Create a small script that flags incomplete records and produces a Markdown summary.
4. **GitHub.com:** Draft an issue with the findings, acceptance criteria, and a verification checklist.

The demonstration emphasizes that the user supplies the purpose and judgment while Copilot helps with structure, syntax, alternatives, and iteration.

## Assessment

Use three lightweight checks:

- **Opening poll:** “After installing Copilot, what stopped you from using it more?”
- **Mid-session check:** Ask the audience to identify which part of Goal–Context–Constraints–Check is missing from a sample prompt.
- **Exit commitment:** Participants write down one real task, the Copilot surface they will use, and how they will verify the result.

## Delivery requirements

- Confirm that the demo accounts and Copilot surfaces are authenticated before the session.
- Use synthetic data only; do not expose customer, employee, or operationally sensitive information.
- Keep backup screenshots or copied outputs for every live demonstration.
- Increase editor and terminal font sizes for a large audience.
- Avoid unexplained developer jargon; define repository, prompt, context, terminal, and script when first used.

## Success measures

- Participants can name a useful first task instead of only naming a Copilot feature.
- Participants can improve a vague prompt by adding context, constraints, and a check.
- Participants leave with one specific experiment they can complete within a week.
