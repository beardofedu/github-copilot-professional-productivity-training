Start with work, not a feature

What kind of help do you need?

02
The prompting pattern

Goal · Context · Constraints · Check

G

Goal

What outcome do I need?

C

Context

What does Copilot need to know?

C

Constraints

What must it use, avoid, or preserve?

C

Check

How will I verify the result?

03
Worked example

Give Copilot less to guess.

Goal Build a repeatable account-health report from CRM, usage, and prior-week exports.

Context Usage keys may require an approved alias map. A five-person team reviews the report every Friday.

Constraints Never modify source files or guess an unmatched account. Use standard Python and explicit rules.

Check Preserve exceptions, test risky rules, run the workflow, and trace report claims to source data.

Tip

A prompt is not a one-time incantation. Ask for a plan, inspect assumptions, test a small result, and refine it.

05
Iterate

Make it a conversation.

  1. 1
    Inspect

    Read the workspace and expose assumptions before editing.

  2. 2
    Plan

    Agree on files, rules, evidence, and decision boundaries.

  3. 3
    Build

    Create the smallest complete end-to-end version.

  4. 4
    Run

    Execute the workflow and inspect actual outputs.

  5. 5
    Review and refine

    Find silent failures and apply only justified changes.

  6. 6
    Package

    Leave a prompt, runbook, tests, outputs, and limitations.

06
Before you use or share it

Run the four-part verification check.

Confident language is not evidence. Open sources, inspect commands, and test results.

My one-week experiment

Turn one useful idea into practice.

Choose a task that takes 15–60 minutes, happens more than once, and has a result you can verify.
