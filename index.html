A repeatable prompt

Goal · Context · Constraints · Check

A simple pattern for turning a vague task into a useful, reviewable outcome.

Goal

What outcome do I need?

Context

What must Copilot know about the source, audience, or workflow?

Constraints

What must it use, avoid, preserve, or limit?

Check

How will I know the result is correct and safe?

From vague to useful

Give Copilot enough to work with.

Weak

“Build the weekly report.”

Agent Mode must guess the sources, joining rules, risk definitions, output contract, and evidence.
Stronger

Goal: Build a repeatable account-health report from CRM, usage, and prior-week exports.
Context: Usage keys may require the approved alias map; a five-person team reviews the result every Friday.
Constraints: Never modify sources or guess an unmatched account; use standard Python and explicit rules.
Check: Preserve exceptions, add tests for risky behavior, run the workflow, and trace report claims to source data.

The live workflow

Multi-source account-health automation.

A five-person team manually combines CRM, product-usage, alias, and prior-week data. Agent Mode turns that work into a repeatable, tested, reviewable capability without hiding unresolved records.

1

Inspect

Read every source and expose reconciliation risks before editing.

2

Build and run

Join approved records, preserve exceptions, and generate actual outputs.

3

Test and review

Prove high-risk rules and look for plausible but incorrect results.

4

Package

Add a runbook and reusable prompt so a teammate can repeat the workflow.

Make it a conversation.

Responsible use

Keep ownership of the result.

Accuracy

Do joins, calculations, and report claims trace back to source records?

Safety

Are source exports immutable and outputs written separately?

Policy

Is the data appropriate for Copilot and the chosen storage location?

Fitness

Do tests, exceptions, and representative inputs cover real conditions?

Confident language is not evidence.
